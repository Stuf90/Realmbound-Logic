# AUTHOR WITH LEVEL GENERATOR

> AGENT FILE. CAVE SPEAK. HUMAN VERSION: `level-generator.human.md`.

## PROBLEM THIS FIX

ALL 5 SHIP CASE (`marrowfenChapel`, `ashwellManor`, `thistledownMarket`, `wrenmoorWatchtower`,
`hollowmereLodge`) TRACE BACK ONE HAND-AUTHOR TEMPLATE: ALWAYS FULL-ROW/COLUMN VICTIM+TRAITOR
CHAMBER + FOUR IRREGULAR CHAMBER, SAME PROP-COUNT PATTERN, + — PART BOARD-SHAPE VARY ALONE NOT FIX —
CLUE SET **ALWAYS** EXACT ONE `exact-chamber` CLUE PER NON-VICTIM CHARACTER + ONE `on-prop` CLUE ON
TRAITOR. ENGINE SUPPORT 20 `InquestPredicate` VARIANT (`types.ts`), ALMOST NONE EVER SHIP REAL
CONTENT. HAPPEN BECAUSE: GIVE "AUTHOR NEW CASE," AGENT (OR HUMAN RUSH) COLLAPSE BACK COPY NEAREST
EXIST LEVEL SHAPE INSTEAD EXPLORE PREDICATE SPACE — NOTHING FORCE VARIETY.

`tools/royal-inquest-generator/` = PROCEDURAL GENERATOR FIX THIS: BOARD SHAPE, PROP PLACE, CAST, CLUE-
PREDICATE MIX = CODE PROPERTY NOW, NOT AUTHOR DISCIPLINE. NOT REPLACE HAND-AUTHOR — GIVE IT RANDOM,
ALWAYS-VALID START POINT.

## CLI

```
npm run inquest:generate -- --difficulty <1|2|3> [--seed <number>] [--out <path>]
```

- `--difficulty <1|2|3>` — REQUIRE. GATE WHICH PREDICATE TYPE CLUE SET DRAW FROM, SAME
  `predicateDifficulty.ts` TABLE HAND-AUTHOR CASE USE.
- `--seed <number>` — OPTION. SKIP → GENERATOR PICK + LOG ONE (`Generated with seed N (rerun with
  --seed N to reproduce this exact case).`) — WHOLE PIPELINE PURE FUNCTION OF SEED, PASS LOG VALUE
  BACK REPRODUCE EXACT SAME CASE.
- `--out <path>` — OPTION. WRITE GENERATE LEVEL AS `.ts` FILE THAT PATH, SAME SHAPE HAND-AUTHOR FILE
  UNDER `src/features/royal-inquest/levels/`. SKIP → PRINT STDOUT INSTEAD.

CLI ALSO RUN GENERATE DEFINITION BACK THROUGH `buildSolveReport` (SAME REPORT `inquest:solve` CLI
USE), PRINT PASS/FAIL SUMMARY BEFORE EXIT — GENERATE CASE SOMEHOW FAIL VALIDATE STILL EXIT NON-ZERO,
NOT SILENT WRITE BROKE FILE (SHOULD NEVER HAPPEN REAL — `generateInquestDefinition` ITSELF GATE ON
`validateInquestDefinition` BEFORE RETURN).

## PIPELINE

CHAMBER COUNT PICK FIRST (`[4, 5]`). BOARD SIZE + CAST SIZE BOTH DERIVE = `chamberCount + 1` — SQUARE
BOARD, CAST FILL EVERY ROW + EVERY COLUMN EXACT ONCE ("FULL-QUOTA" CAST, NOT PARTIAL). LOAD-BEAR
CHOICE, NOT ARBITRARY — SEE "WHY SQUARE FULL-QUOTA CAST" BELOW.

SIX STAGE, EACH OWN FILE UNDER `tools/royal-inquest-generator/`:

1. **`chamberLayout.ts`** — GROW CHAMBER SEED REGION-GROW (BFS-STYLE FRONTIER EXPAND) FROM
   `chamberCount` RANDOM SEED CELL ON `size x size` BOARD TILL EVERY CELL ASSIGN — MAKE CHAMBER SHAPE
   IRREGULAR NOT RECTANGLE. CHAMBER UNDER 5 CELL (VALIDATOR FLOOR) MERGE INTO NEIGHBOR — DROP COUNT
   BELOW REQUEST → BOARD NO LONGER SIZE `chamberCount + 1` → CALLER RETRY WHOLE LAYOUT, NOT PATCH.
   EACH CHAMBER GET `TileEnvironment` RESTRICT `room`/`church`/`royalRoom` ONLY — ONLY ENV WITH SEAT-
   KIND PROP AT ALL (SEE "WHY SEAT-CAPABLE ENV ONLY" BELOW) — CAP SO NO ENV REPEAT MORE THAN OWN
   DISTINCT NON-SPAN SEAT-ASSET COUNT (`room`: 2, `church`: 1, `royalRoom`: 2), PLUS SOFT BIAS AGAINST
   REPEAT NEIGHBOR ENV.
2. **`solutionAndCast.ts`** `chooseChamberAssignment` — BEFORE ANY PROP EXIST — SEARCH (CHEAP, PURE
   COMBINATORIC) FOR FULL ROW/COLUMN PERMUTATION WHOSE CHAMBER GROUP EXACT "ONE CHAMBER GET TWO CELL,
   EVERY OTHER CHAMBER GET EXACT ONE." DECIDE WHERE EVERYONE SIT BEFORE DECIDE WHAT IN ROOM.
3. **`propPlacement.ts`** — FORCE SEAT PROP (`PropAssetId` NOT REUSE ACROSS CHAMBER) ONTO EACH
   CHAMBER ASSIGN ANCHOR CELL FROM STAGE 2, THEN BLOCK 0-2 OTHER CELL PER CHAMBER FOR LEGAL DECORATIVE
   PROP (FILTER `propsByEnvironment[environment]` BY `propKindByAsset[id] === 'decorative'`), NEVER
   TOUCH STAGE-2 CELL, AVOID REPEAT SAME PROP ASSET TWO ORTHOGONAL-ADJACENT CELL. DELIBERATE SKIP
   `-left`/`-right` TWO-CELL-SPAN PROP ENTIRE (SEE "SCOPE CUT" BELOW).
4. **`solutionAndCast.ts`** `buildCastAndSolution` — LABEL STAGE-2 POSITION WITH CAST: UNIQUE
   AVATAR/NAME PER OCCUPANT, PAIR CHAMBER ANCHOR OCCUPANT BECOME TRAITOR, SECOND OCCUPANT BECOME
   VICTIM.
5. **`clueGeneration.ts`** — ACTUAL FIX FOR SAMENESS PROBLEM. BUILD WEIGHT CANDIDATE POOL EVERY
   CLUE-LEGAL PREDICATE TYPE (EXCLUDE `exact-row`/`exact-column`, CHARACTER-PAIR
   `beside`/`not-beside`, + `direction-from` — SEE "WHAT EXCLUDE" BELOW), GATE
   `predicateDifficulty.ts` AGAINST REQUEST DIFFICULTY, INSTANTIATE ONLY WHEN AUTHOR SOLUTION
   ACTUAL MAKE TRUE. GIVE EACH NON-VICTIM CHARACTER ONE ANCHOR CLUE, THEN RUN **REPAIR LOOP**:
   RE-SOLVE `solveInquestDefinition`/`checkVictimElimination` (SAME AUTHOR-TIME SOLVER
   `validateInquestDefinition` USE); UNDER-CONSTRAIN → ADD ANOTHER TRUE, LEGAL CLUE; BOUND RETRY,
   THEN BAIL SO CALLER REGENERATE WHOLE LAYOUT INSTEAD LOOP FOREVER ON UNFIX CLUE SET. WITH STAGE
   2-4 ANCHOR ALREADY DONE, `exact-chamber` + `on-prop` ALONE USUAL ENOUGH REACH UNIQUE SOLUTION AT
   DIFFICULTY 1 — REPAIR LOOP MOSTLY PATCH SMALL GAP, NOT CARRY WHOLE PUZZLE.
6. **`generate.ts`** — ORCHESTRATE 1-5, RETRY **WHOLE** PIPELINE (NOT JUST ONE STAGE) UP ~50 TIME ON
   ANY STAGE FAIL, GATE FINAL `validateInquestDefinition` CALL. THROW DESCRIBE ERROR IF EVERY
   ATTEMPT FAIL; NEVER RETURN INVALID DEFINITION.

`emitLevelFile.ts` THEN SERIALIZE ACCEPT `InquestDefinition` INTO `.ts` SOURCE STRING MATCH
HAND-AUTHOR FILE SHAPE EXACT, SO OUTPUT FREE HAND-EDIT AFTER, NOT BLACK BOX.

## WHY SQUARE FULL-QUOTA CAST

EARLY VERSION THIS GENERATOR PICK `rows`/`columns` INDEPENDENT 5-7 + CAST SIZE INDEPENDENT 4-7, PER
LITERAL READ ORIGINAL BRIEF. STRESS-TEST DIRECT (RUN EACH STAGE THOUSAND TIME, NOT JUST TRUST 50-
ATTEMPT RETRY BUDGET) SHOW CONVERGE UNDER 1% TIME AT DIFFICULTY 1-2: PARTIAL-QUOTA CAST LEAVE MOST
ROW/COLUMN UNUSE BY ANYONE, SO EVEN EVERY CHARACTER CHAMBER PIN, VICTIM USUAL HAVE MANY LEGAL CELL
LEFT, NOT ONE ELIMINATION CHECK NEED — NO DIFFICULTY-1/2 PREDICATE CAN NARROW GENERIC INTERIOR
CHAMBER CELL FURTHER. MAKE CAST SIZE EXACT = BOARD ROW/COLUMN COUNT FIX THIS STRUCTURE: ONCE EVERY
NON-VICTIM CHARACTER PLACE, EVERY ROW + COLUMN EXCEPT ONE USE, FORCE VICTIM CELL PURE ELIMINATION,
INDEPENDENT CHAMBER SHAPE.

## WHY SEAT-CAPABLE ENV ONLY

CHAMBER MEMBERSHIP ALONE NOT PIN EXACT CELL (SEE ABOVE) — GENERATOR INSTEAD ANCHOR EACH CHAMBER
OCCUPANT TO REAL SINGLE-CELL FACT: `on-prop` CLUE AGAINST THAT CHAMBER SEAT. `garden`/`kitchen`/
`dungeon` HAVE NO SEAT-KIND `PropAssetId` AT ALL, SO CHARACTER PLACE THERE NEVER GET THIS ANCHOR —
GENERATOR RESTRICT `room`/`church`/`royalRoom` ONLY. THIS CAP MAX CHAMBER COUNT AT 5 (COMBINE SEAT-
ASSET SUPPLY ACROSS THOSE THREE ENV, EXCLUDE `-left`/`-right` VARIANT), WHY BOARD SIZE TOP OUT 6x6
NOT 7x7 — ANOTHER DELIBERATE DEPART FROM ORIGINAL 5-7 RANGE, SAME SOLVER-VERIFY-CONVERGE REASON AS
FULL-QUOTA CAST ABOVE.

## WHY REPAIR LOOP, NOT FORWARD SOLVER

`solver.ts` BACKTRACK SEARCH BUILD *CHECK* CLUE SET, NOT *BUILD* MINIMAL ONE FROM SCRATCH — TURN
INTO GENERATOR MEAN WRITE SECOND, DIFFERENT CSP-MINIMIZE ALGORITHM. INSTEAD, GENERATOR WORK LIKE
HUMAN AUTHOR: PLACE SOLUTION FIRST, GUESS PLAUSIBLE CLUE SET (EVERY CANDIDATE CHECK TRUE AGAINST
THAT SOLUTION BEFORE ADD, SO CLUE SET NEVER *INCONSISTENT* — ONLY *UNDER-CONSTRAIN*), THEN USE SAME
SOLVER `validateInquestDefinition` ALREADY RUN AS ORACLE DETECT UNDER-CONSTRAIN + PATCH ITERATE.
REUSE EXIST SOLVER EXACT AS-IS, COST = PROBABILISTIC (BOUND RETRY, NOT GUARANTEE-MINIMAL CLUE
COUNT) NOT DETERMINISTIC-OPTIMAL.

## WHAT EXCLUDE FROM CANDIDATE POOL (NOT GENERATE-THEN-DISCARD)

- `exact-row`/`exact-column` + CHARACTER-PAIR `beside`/`not-beside` — `validateInquestDefinition`
  REJECT OUTRIGHT, SO GENERATOR NEVER HAVE THESE IN CANDIDATE POOL AT ALL.
- `direction-from` — ALWAYS VACUOUS AGAINST FULL ROW/COLUMN-PERMUTATION SOLUTION (EVERY GENERATE
  CASE USE), PER `clues-and-predicates.cave.md`. DIFFICULTY-2-LEGAL IN PRINCIPLE, BUT GENERATOR
  NEVER SELECT SINCE NEVER TRUE AGAINST AUTHOR SOLUTION.
- `-left`/`-right` TWO-CELL-SPAN PROP (`bookshelf-left/right`, `dining-table-left/right`,
  `kitchen-worktable-left/right`, `wooden-bench-left/right`, `church-pew-left/right`) — PLACE CORRECT
  NEED FIND ADJACENT SAME-CHAMBER CELL PAIR, PLACEMENT-MODEL COMPLICATE ORTHOGONAL TO CLUE-VARIETY
  PROBLEM THIS GENERATOR TARGET. DELIBERATE SCOPE CUT, NOT OVERSIGHT — GENERATOR ONLY EVER EMIT
  PLAIN SINGLE-CELL PROP ASSET FOR GIVE KIND.
- `garden`/`kitchen`/`dungeon`/`hallway` CHAMBER ENV — NEVER PICK AS GENERATE CHAMBER ENV (SEE "WHY
  SEAT-CAPABLE ENV ONLY" ABOVE FOR FIRST THREE; `hallway` `propsByEnvironment` ALLOW-LIST EFFECTIVE
  EMPTY ENTIRE). HUMAN HAND-EDIT GENERATOR OUTPUT FREE REPAINT CHAMBER ANY THESE AFTER.

## USE AS START POINT, NOT FINAL PRODUCT

RECOMMEND FLOW (SEE `.claude/skills/royal-inquest-puzzle-design/SKILL.md`):

1. `npm run inquest:generate -- --difficulty <N> --out src/features/royal-inquest/levels/<slug>.ts`
2. HAND-POLISH: RENAME CHAMBER/CHARACTER/CASE TITLE, ADJUST CLUE WORD, OPTION ADD ONE BESPOKE
   HAND-WRITE CLUE ON TOP.
3. `npm run inquest:solve -- --file src/features/royal-inquest/levels/<slug>.ts` RE-VALIDATE AFTER
   HAND EDIT.
4. REGISTER NEW LEVEL IN `src/features/royal-inquest/levels/index.ts`.
